## 2. Objectives

1. Each owner places every step of one front desk or admin job of their own in a Zone.
2. Each owner writes one rule, with one exception, for a step they placed Below.
3. Owners can explain how answers became rules, holds and dashboard numbers, with no model deciding any of it.
4. Each owner sees an ROI estimate on their own hours.

## 3. The job (practice fab shop, synthetic)

Front desk: a new inquiry.

| Step | Source | Done by |
|---|---|---|
| 1. Inquiry arrives | Email or web form | Document intake reads it |
| 2. Sort by intent | Owner's categories | Code applies the categories |
| 3. Find the customer | CRM export | Code looks it up |
| 4. Hold if information is missing | Owner's hold rule (L4.1) | Code holds it |
| 5. Draft the reply | Owner's words (L1.1) | Local model writes the short text only |
| 6. Approve | Owner's approval rule (L4.2) | A person approves |
| 7. Follow up | Owner's timing (L3.5) | Draft at the set day |

Admin: a supplier invoice.

| Step | Source | Done by |
|---|---|---|
| 1. Invoice PDF arrives | Email | Document intake reads it |
| 2. Pull the fields | Vendor, PO number, amount, due date | Extracted with the page it came from |
| 3. Match to the purchase order | PO list | Code matches |
| 4. Hold on a mismatch | Owner's hold rule | Code holds it |
| 5. Confirm | Office manager | A person confirms |
| 6. Due-date and unpaid alerts | Due dates | Code alerts |
